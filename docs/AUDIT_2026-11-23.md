## 1. GitHub issue #1 — Android/Termux `npm install` fails (ROOT CAUSE CONFIRMED)

Screenshot: `npm error code EBADPLATFORM … onnxruntime-node@1.21.0: wanted {"os":"win32,darwin,linux"} (current: {"os":"android"})`.

- `@huggingface/transformers` (4.2.0 and still 4.3.2) lists `onnxruntime-node` + `sharp` as **hard** deps ✔.
  LATCH never uses them — Vite resolves `transformers.web.js`, which stubs both.
- **Workaround that works** (tested on macOS, not Termux): local stub packages
  `"onnxruntime-node": "file:./stubs/onnxruntime-node"` (and `sharp`) in deps +
  `"overrides": { "onnxruntime-node": "$onnxruntime-node", "sharp": "$sharp" }`.
  Bonus: drops ~300 MB of native binaries from installs *and* from the Electron package.
- Does NOT work: own `optionalDependencies`, `--omit=optional`, `--os`, relative `file:` inside `overrides`.
  `npm install --force` works today as an immediate reply to the reporter.
- Upstream: no Termux issue; transformers.js #1963 / PR #1814 (lazy import) still open.
- Also needs: Vite/esbuild/rollup android-arm64 binaries (they exist) — not yet verified end-to-end on Termux.

## 2. Security — fix before anything else

1. **Shared-flow → arbitrary code (web) → arbitrary file write + launch (desktop).** ✔
   - `code.ts:9-13` says the real boundary for untrusted flows is "the import trust-prompt (stores/flows.ts)". **That prompt does not exist**: `importFlows` imports Function/Expression code silently; `describeCapabilities` is called only by tests. Opening a shared `.json` and pressing Play runs in-process JS (sandbox escape acknowledged in-code).
   - In Electron, the preload exposes `shell:openPath`, `showItemInFolder`, `assets:setBasePath`, `app:getPath`, and catch-all `on/once` IPC listeners (`src/main/preload.ts:25-41`) that **the renderer never uses** ✔. Combined: retarget the asset dir (`index.ts:330`) → write any file (`:344`) → launch it (`:176`).
   - `sandbox: false` (`index.ts:42`) with a stale "native modules" justification; no IPC sender validation, no `will-navigate` guard, no permission handler, no CSP, no fuses.
   - **Fix:** delete the unused bridge surface (hours, any Electron version); build the import trust prompt using the existing `describeCapabilities`; then Electron 29 → 45 with sandbox on.
2. **Electron 29 is EOL since 2024-08**: 45 advisories incl. context-isolation bypass, contextBridge prototype setters, `openPath` null-byte bypass; ~2.5 yrs of missing V8 fixes. No auto-updater.
3. **npm audit** (75 total / 17 prod): all 5 criticals are dev-only/unreachable; prod Vue-SSR XSS, nanoid, ws, postcss/rollup are unreachable in this SPA. Only shipped+plausible: DOMPurify inside monaco 0.55 (needs monaco 0.58.0 or override). `npm audit fix` (no `--force`) clears nearly all prod findings.
4. **MediaPipe WASM loaded from `@latest`** (`MediaPipeService.ts:329-330`) ✔ — production is running 0.10.32 JS against **1.2.3** WASM right now (unverified at runtime). Also: MediaPipe 1.x adds Google usage telemetry (`odml.pa.googleapis.com`, consent required per README) — a privacy decision before ever bumping. **Pin both URLs to the installed version now.**
