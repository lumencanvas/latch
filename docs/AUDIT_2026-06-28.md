# LATCH Deep Audit — 2026-06-28

Comprehensive audit of the node library (UI, functionality, inter-node
compatibility, lifecycle), the subflow system, and product/UX gaps measured
against the leading node-based creative tools (TouchDesigner, Max/MSP, vvvv
gamma, Cables, Notch, Blender, Unreal Blueprints, Resolume).

**Method.** Nine parallel read-only investigations over current `main`
(HEAD `d390b05`, v1.2.14): controls/UI system, subflows, node defs+executors in
three category groups, the type system & connection layer, lifecycle/leak
coverage, editor/workflow feature inventory, and competitor research. Every
finding below was verified in source and carries `file:line` evidence. Items
already tracked in `AUDIT_2026-06-16.md` / `AUDIT_2026-06-19.md` /
`NODE_LIBRARY_REVIEW_2026-06-18.md` are flagged **[tracked]** and not
re-litigated.

**Ground-truth posture.** The codebase is in good shape. The recurring leak
class CLAUDE.md warns about (unwired per-node state) is **closed** — every
stateful executor map now has a wired `gc*` + `disposeAll*` path. Editor
tooling is more complete than expected (undo/redo, copy-paste-with-params,
fuzzy node search, minimap/snap/fit, autosave, a full Control Panel perform
surface, a console+error Debug panel). The high-value gaps are concentrated in
five places: **subflows (broken at runtime)**, **the modulation story (params
with no input ports)**, **silent texture/coercion traps**, **the control
system (two renderers, dropped min/max, custom controls not first-class)**, and
**AI/observability + a few missing protocols/primitives**.

---

## 1. Headline findings

1. **The subflow system is functionally dead at runtime.** It looks complete
   (create-from-selection, ports, unpack, keybinds) but no subflow ever
   produces output, and an instance node renders with **zero ports**. This is
   the single biggest gap in the app and matches the maintainer's instinct that
   "something is missing." (§A)
2. **Pervasive "tips promise modulation that doesn't exist."** Dozens of
   visual/audio/3D/timing nodes tell the user to "drive Intensity from an LFO"
   or "automate Pixels from an envelope," but the parameter is a control with
   **no input port**, so it can't be wired. (§C)
3. **Silent black-frame and coercion traps.** The connection layer *promises*
   number/boolean coercion the engine never performs (so `boolean → add`
   silently yields garbage), and several texture paths render black with no
   error when fed video- or cross-renderer-context textures. (§D)
4. **The control system has structural debt.** Two/three divergent control
   renderers, **127 `number` controls silently ignore their declared
   `min`/`max`**, no units/precision display, and the rich custom controls
   (knob, XY, envelope, EQ, waveform) are not first-class control types. (§B)
5. **AI nodes have no error/observability surface.** Not one AI node exposes an
   `error` output, most hardcode the model, and download progress isn't shown —
   poor for unattended installations. (§E)

## A. Subflow system — broken at runtime (P0)

Independently flagged by three investigations (subflow design, lifecycle,
competitor). The store-level graph surgery (create/edit/unpack, Ctrl+G/E/
Shift+G) works and is tested; **runtime execution and the instance UI were
never wired up.**

- **[P0] Subflows never execute.** `subflowExecutor` reads `_getSubflow` and
  `_executeNode` from the control map (`executors/subflow.ts:138,151`), but the
  engine builds the control map only from definition defaults + `node.data`
  (`ExecutionEngine.ts:355-375`) and never injects them. Result: the executor
  always returns `{_error: 'Subflow resolver not available'}` or null outputs;
  the entire internal topo-sort (`subflow.ts:166-225`) is unreachable dead code.
- **[P0] Instance node has no definition → zero ports.** `createSubflowFrom
  Selection` sets `data.nodeType:'subflow'` (`flows.ts:824`), but the registry
  only defines `subflow-input`/`subflow-output` (`registry/subflows/index.ts`).
  BaseNode resolves ports from `definition` or `_dynamicInputs/_dynamicOutputs`
  (`BaseNode.vue:80-127`); the instance sets neither, so it renders as a box
  with no handles — yet `createSubflowFromSelection` creates edges to those
  non-existent handles (`flows.ts:841,854`).
- **[P0] Internal state would collide across instances.** Internal nodes are
  run with their own fixed ids (`subflow.ts:214`); every executor keys module
  state by `ctx.nodeId`. Two instances of one subflow would share oscillator
  phase, `smooth` history, timers, and live audio nodes. Fix requires a
  compound key like `${instanceId}::${internalId}`.
- **[High] Async/audio/WebGL nodes can't work inside a subflow.** The executor
  is a synchronous `NodeExecutorFn` calling a synchronous `executeNode`; the
  real engine `executeNode` is `async` and awaited (`ExecutionEngine.ts:337,
  414`). AI/HTTP/WebLLM/MediaPipe/fire-and-latch Promises would be dropped.
- **[High] No timing context** (`deltaTime`/`totalTime`) is threaded to internal
  nodes → animated nodes would freeze/NaN.
- **[High] Internal executor state has no GC/dispose path** — `gcSubflowState`
  only clears the context map (latent leak once execution is wired).
- **[High] Navigation strands you.** `editSelectedSubflow` calls
  `setActiveFlow(subflowId)` (`EditorView.vue:617`) but FlowTabs filters out
  subflows (`FlowTabs.vue:11`) — no tab, no breadcrumb, no way back.
- **[High] No reuse/instancing** — subflows never appear in the palette; the
  only creation path is one-in-place. Nesting is structurally impossible and
  there's no recursion guard.

**Recommendation.** Treat this as a rebuild, not a patch. Execute subflows by
inlining internal nodes into the main async topo loop with instance-namespaced
ids (solves execution, async, timing, state isolation, GC, dirty-mode in one
move). Then add: a real `subflow` instance definition that emits dynamic typed
ports (`_dynamicInputs/_dynamicOutputs` is already engine-supported,
`ExecutionEngine.ts:460-475`); palette publishing; breadcrumb navigation; a
recursion depth guard; and (P3) TD-style custom parameters on the instance.
Grade the rebuild against the 12-point checklist in §H.2.

## B. Control / UI system (P0–P2)

- **[P0] 127 `number` controls silently ignore `min`/`max`.** The `number`
  branch binds only `:step` (`BaseNode.vue:666`; the `slider` branch at
  `:606-608` does bind them); declared
  `props.min/max` (e.g. `slew-limiter.ts:17-18`) are dropped, so users can type
  out-of-range values. Bind `:min`/`:max`.
- **[P1] No units/precision display anywhere.** No renderer reads `units`/
  `suffix`/`precision`; units are baked into label strings. Slider readouts are
  hard-coded to `toFixed(2)` (`BaseNode.vue:612`, `PropertiesPanel.vue:649`) —
  wrong for Hz/ms/dB and integers. Add `props.units` + `props.precision`.
- **[P1] Two/three divergent control renderers.** PropertiesPanel handles 10
  types, BaseNode inline handles 6 (excludes `code`/`connection`/`asset-picker`/
  `template-select`), ControlPanelView has bespoke per-nodeType widgets. A node
  with a `connection` control shows it in the inspector but **renders nothing on
  the node body**. New types must be added in 2–3 places. Extract one
  `<ControlRenderer>`. Also unify the two conditional-visibility mechanisms:
  `visibleWhen` (BaseNode) vs `props.showWhen` (PropertiesPanel).
- **[P1] Rich custom controls are not first-class.** RotaryKnob/EQEditor/
  EnvelopeEditor/WaveformEditor/PianoKeyboard are only reachable through bespoke
  node `.vue` components registered in `registry/components.ts` — there is no
  `type:'knob'|'xy'|'envelope'`. Adding a knob to `filter` requires a whole
  custom component. Wire them into the control-type switch.
- **[P2] Missing control types** (each currently faked with multiple plain
  controls): XY pad / 2D-vector (`xy-pad` is a one-off node; math/noise fake
  vectors with separate x/y/z), `range` dual-slider (faked by `clamp`,
  `in-range`, `random`, `wrap`, `remap`, knob min/max), curve/bezier easing
  editor (`easing` is a select + static preview), gradient/color-ramp editor
  (`color-ramp` is a static preview), button/momentary, stepper, searchable
  dropdown.
- **[P2] No drag-to-scrub on `number`/`slider`.** Only RotaryKnob and the
  Control-Panel fader implement it. Generalize it to the standard numeric field
  (the single most-felt affordance vs TD/vvvv/Max).
- **[P2] Reset & fine-drag.** No double-click-to-reset on number/slider; knob
  resets to range *midpoint*, not `default` (`RotaryKnob.vue:177-180`). No
  fine(Shift)/coarse drag on the knob; **RotaryKnob is mouse-only** (no
  touch/pointer handlers) despite a mobile layout.
- **[P2] A11y.** Canvas custom controls have no keyboard/ARIA (RotaryKnob,
  Envelope/Waveform/EQ editors); control labels aren't associated with inputs
  (no `for`/`id`); toggle exposes no `aria-checked`; color control has no hex
  text entry. Add `role="slider"` + arrow-key handling + label association.

## C. The modulation gap — params without input ports (P1)

A recurring, high-leverage pattern: parameters are controls with **no
corresponding input port**, so they can't be modulated — even when the node's
own tip tells the user to modulate them. Executors already apply input ports
each frame, so adding ports is low-cost.

- **[P1] image-fx-* params aren't wireable** — `image-fx-glitch/kaleidoscope/
  pixelate/posterize/rgb-shift/scanlines/dither/chroma-key` declare only a
  `source` texture input and build controls via `generateControlsFromUniforms`
  (e.g. `image-fx-glitch.ts:14-16`), yet their tips say "Drive Intensity from an
  LFO" / "Connect a Time node to Rotation" / "Automate Pixels from an
  envelope." Generate matching number input ports from the same uniform list
  (the Shader node already does uniform→port, `shader.ts:14-16`).
- **[P1] Audio effects can't be automated** — `reverb` (decay/wet/preDelay),
  `audio-delay` (feedback/wet), `audio-distortion` (wet, despite the tip "Drive
  Drive Amount from an envelope or LFO"), `audio-bitcrusher` (wet),
  `audio-compressor` (ratio/attack/release/knee + no sidechain key),
  `filter` (**Q has no port**) — all control-only. Add `wet`/`mix`,
  `feedback`, `Q`, `ratio` input ports. (Evidence: `reverb.ts:11-13`,
  `audio-delay.ts:11-14`, `filter.ts:11-14`, etc.)
- **[P1] 3D materials/lights have no color/emissive ports** — `material-3d`
  and all four lights expose color/emissive as controls only
  (`material-3d.ts:25,31,32`, `directional-light-3d.ts:22`). Audio-reactive
  light color / material tint / emissive glow — a marquee Notch/TD use case —
  is currently impossible. Add color (vec3/data) + `emissiveIntensity` ports.
- **[P2] Timing params lack CV inputs** — `interval.interval`, `delay.delay`
  are control-only (`interval.ts:115`, `delay.ts:14`); `metronome.bpm` does it
  right (control + input). Add ms input ports.

## D. Type system & silent compatibility traps (P0–P1)

A real validation layer exists (`utils/connections.ts` + `:is-valid-connection`
on Vue Flow) and blocks the egregious mismatches (texture→number, audio→string).
The gaps are *honesty* and *silent texture failures*.

- **[P0] The matrix promises coercion the engine never performs.**
  `connections.ts:20,26` declare `number→string`, `number→boolean`,
  `boolean→number`, `boolean→string` "compatible," but executors read raw with
  TS-only casts (`index.ts:215-217`: `(ctx.inputs.get('a') as number) ?? 0`).
  A `boolean true` into `add` → `true+0=1`; `?? 0` only catches null, never a
  wrong type. **Fix:** coerce at the input boundary in `getNodeInputs`
  (`ExecutionEngine.ts:315-332`) using the target port's declared type — ~15
  lines, kills the whole NaN/concat class. (Or remove the coercion edges so
  they're blocked.)
- **[P0] Video-backed `THREE.Texture` → Shader `iChannel` renders black.** The
  shader path pushes a `THREE.Texture` uniform unchanged (`visual.ts:607-622`);
  the video→canvas conversion only fires for a *raw* video/canvas element, not a
  texture whose `.image` is a video. Effect nodes already guard this via
  `resolveEffectSource` (`visual.ts:691-723`) — reuse it in the shader path.
- **[P0] `render-3d` (depth mode) emits a cross-context `WebGLTexture`** typed
  `texture` (`render-3d.ts:17`); consumed via `createTextureFromWebGL` on a
  *different* renderer (`visual.ts:663`) → black, silently. The no-depth path
  is safe (outputs a canvas). Make depth canvas-backed too (copy the emulator's
  blit, `emulation.ts:88-110`). The `displacement` map input has the same
  unguarded raw-texture read (`visual.ts:1282`).
- **[P1] Multiple edges into a non-`multiple` input** are silently allowed;
  `getNodeInputs` last-writer-wins by edge order (`ExecutionEngine.ts:319-329`).
  `addEdge` only dedupes exact duplicates (`flows.ts:325-356`). Replace the
  existing edge when the target port isn't `multiple`.
- **[P1] `required` and `multiple` flags are enforced/rendered nowhere**
  (`stores/nodes.ts:56-57`; no consumer). `render-3d` marks inputs required;
  inert. Render a required-but-unconnected indicator.
- **[P1] `any` (92 uses) is a true wildcard both directions** — necessary for
  generic gate/switch/coalesce, but the clasp/ble value ports use `any` for
  what are really typed JSON/string payloads, so two `any` ports can connect
  with incompatible runtime values (e.g. a Tone audio object into math → NaN).
  Declare known types where they exist.
- **[P2] Loose 3D `data` widening** — `transform3d→data`, `array→data`,
  `light3d→object3d` permitted (`connections.ts:34,35,53`); the strict subtype
  rules otherwise hold (you can't wire geometry into material — good).

## E. Node-level functionality & UI (P1–P3)

### Logic / math / timing (correctness first)
- **[P1] `latch` & `sample-hold` are level-triggered, not edge-triggered**
  (`utility.ts:302-323,288-300`) despite docs — feeding a gate makes
  sample-hold a pass-through. The metronome/tap-tempo/step-seq executors do
  proper rising-edge detection; these two weren't updated.
- **[P1] `random` re-rolls every frame** (`index.ts:284-298`) with no
  sample-on-trigger — unusable as "pick one value on bang." Add a trigger input
  that re-rolls on rising edge.
- **[P1] `lfo` has no `phase` output and no `reset`/`sync` input** — can't be
  beat-aligned (the metronome already exposes `phase`). Add `phase`, `reset`,
  and a unipolar/bipolar toggle.
- **[P1] `power` Log mode is misleading + finite-guard gap** (`index.ts:366,
  381`): "Log" is log base `exponent` (defaults to 2, with no label hint), and
  the `isNaN`→0 guard lets `±Infinity` through (e.g. `log(0)` → `-Infinity`;
  `sqrt(-1)` → NaN→0 silently).
- **[P2] Missing primitives** creative coders expect: `atan2` (two-arg — the
  node for "angle to a point"; `trig` only has single-arg `atan`), two-input
  `min`/`max`, a `phasor`/`ramp` timing node, a dedicated `edge` (rising/falling/
  both) logic node, gate-length/pulse, clock divider.
- **[P2] boolean results emitted as `1`/`0` but typed `boolean`** across logic/
  data (`index.ts:624-641`, `utility.ts:322`) — Monitor shows `1`, `type-of`
  reports `number`. Pick one convention.
- **[P2] control-id == port-id shadowing** on `modulo`, `power`,
  `tween-to-target`, `compare`, `equals`, `and`, `or`, `gate`, `in-range`.
  Executors resolve precedence, but verify BaseNode hides the control when the
  port is wired; newer signal/spring nodes avoid the pattern.
- **[P3] No inverted output** on comparison/boolean nodes; `select` compacts
  away unwired inputs so the index no longer maps to the labeled port
  (`index.ts:660-671`). `array-sort` can't sort objects by key
  (`data.ts:270-282`); missing `array-flatten`/`array-chunk`, `string-repeat`,
  `char-code`/`from-char-code`.

### Audio / visual / 3D
- **[P2] Gain/volume unit inconsistency** — `gain` is **linear**
  (`audio.ts:351,355`, bare unbounded number) while oscillator/player/output use
  **dB**. Same-looking "Volume" means different things. Unify + use ranged
  sliders.
- **[P2] Direct `.value =` per frame zippers** on automated audio params
  (`audio.ts:156,355,398`); use `rampTo`/`setTargetAtTime`.
- **[P2] No feedback (frame-delay) visual node** — the cornerstone of VJ/TD
  trails/infinite-zoom. `blur.passes` control is dead (executor hard-codes 2,
  per `VISUAL_SYSTEM_AUDIT.md:572`). Add feedback; wire `passes`.
- **[P2] Missing dimension/alpha outputs** on effect nodes (`blend`, `blur`,
  `color-correction`, `displacement`) — downstream can't get resolution after
  the first effect.
- **[P2] No filter response-curve control** — reuse the EQEditor pattern for a
  `FilterResponseEditor`. `audio-analyzer` doesn't expose the FFT array it
  already computes (`audio.ts:276`); add a `spectrum` output + 0–1 smoothing
  slider.
- **[P2] 3D breadth** — no instancing, no clearcoat/transmission controls on
  `physical`, no bloom/SSAO/DOF post-FX (despite `render-3d` exporting depth),
  no environment/HDRI, no orbit camera, no GLTF animation-mixer playback.
- **[P3] Taxonomy drift** — `webcam` is `category:'inputs'` but lives in
  `visual/`; OpenCV nodes are `category:'visual'`. `main-output` has zero
  controls (no resolution/fit/aspect); only one output node exists (no
  recorder/second-window/NDI).

### AI / OpenCV / connectivity / clasp / messaging
- **[P1] No `error` output on any AI node** — the executor computes the failure
  but it has nowhere to flow; worst for unattended installs. Add `error` (+
  optional `progress`/`done`).
- **[P1] Stale `connectivity.md`** — documents `url`/`autoConnect` controls, but
  v2 mqtt/websocket use a single `connection` control (`websocket.ts:21`,
  `mqtt.ts:25`). Regenerate from live defs.
- **[P2] Most transformers.js AI nodes hardcode the model** (no `model`
  control; only YOLO/depth/VLA/LLM have one). Add an editable `select`.
- **[P2] `connection`/`template-select` render only in the inspector** — a
  WebSocket/MQTT/CLASP node with only a `connection` control shows an empty
  body (`BaseNode.vue:213-221`). Add a compact inline picker (pair with the
  existing `NodeConnectionStatus` dot).
- **[P2] No DMX/Art-Net/sACN, no raw UDP/TCP** (grep: only http/ws/mqtt/osc/
  midi/serial/ble). Art-Net via the OSC WebSocket-bridge pattern is the
  highest-value connectivity addition for the target audience. (OSC *does*
  exist — UDP-bridged.)
- **[P2] `clasp-stream` lacks an `error`/`connected` surface** (only `sent`);
  CLASP connectionId is free-text string-matching (a typo silently breaks the
  link). Messaging channels are case-sensitive with no autocomplete (docs warn
  about `Volume` vs `volume`); add a channel dropdown + dead-channel GC.
- **[P3] Code node async rejections bypass the `error` output**
  (`code.ts:122` doesn't `.catch()` a thenable). Note: the Function/Expression
  "sandbox" was **materially hardened** since `AUDIT_2026-06-16.md` — a
  `SANDBOX_PREAMBLE` now shadows host globals and the label was corrected
  ("restricted — no DOM/network/storage globals"). Update the audit docs.

## F. Reliability / lifecycle (P1–P3)

**The core contract holds.** Every stateful executor map has a wired `gc*`
(per-node, via `updateGraph`) + `disposeAll*` (via `stop()`). Per-node executor
exceptions are isolated (`ExecutionEngine.ts:387-447`) — one throwing node can't
break the frame loop. Confirmed **fixed** since prior audits: BleAdapter listener
removal, AI worker `onerror` rejecting pending requests (via `WorkerFacade`),
webcam/http per-frame storms, Tone-node-after-dispose restart guard.

Remaining (all *inside* otherwise-wired paths):
- **[P1] Oscilloscope/Equalizer leak their Tone analyser** — cleanup
  `.disconnect()`s but never `.dispose()`s the `Tone.Waveform`/`Tone.FFT`, so an
  `AnalyserNode` leaks on every add/remove/stop (`index.ts:1016-1020,1077-1081,
  1206-1222`; rewire branch `:1095`).
- **[P1] CLASP video-receive never stops its `captureStream`/`<video>`**
  (`clasp.ts:967-985` created; dispose helper doesn't stop tracks or pause the
  element).
- **[P2] CLASP video-send double-connect race** — `broadcasting=true` is set
  after `await connect()` (`clasp.ts:1112-1120,1220`); two frames in the await
  window both build a client, one leaks. Set a synchronous guard before the
  await.
- **[P2] GPU texture leaks** — per-frame untracked `DataTexture` from
  `createTextureFromWebGL` on raw-WebGLTexture inputs (`visual.ts:592,614,663`,
  `3d.ts:90`; bounded — most producers emit `THREE.Texture`); material `.map`s
  and light `shadow.map` render targets not freed in `dispose3DNode` (cache the
  DataTexture per uniform; dispose shadow maps unconditionally; dispose material
  maps only at the owning cache layer to avoid the shared-texture hazard).
- **[P3] `lastConnectAttempt` keys never cleaned** in mqtt/websocket/http
  (`mqtt.ts:47`, `websocket.ts:48`, `http.ts:60`) — bounded, self-clears on
  success; clear in each `disposeAll*` for convention compliance. Confirm
  ws/mqtt connect-backoff landed (http did) — otherwise a battery/CPU burn for
  installations [tracked].

## G. Editor / workflow / product (P0–P3)

LATCH is competitive here. Gaps:
- **[P0] Undo doesn't cover control/param value changes** — the history stack
  exists (`stores/history.ts`, 20 entries, Ctrl+Z/Shift+Z) and wraps add/delete/
  move/connect/paste/subflow, but `updateNodeData` param edits aren't wrapped
  (`BaseNode.vue:343`, `PropertiesPanel.vue:136`). Wrap them, debounced per
  control so a slider drag collapses to one entry.
- **[P1] No per-node error visual state** — errors are recorded
  (`runtime.ts:137-185`) and shown in a Debug tab + StatusBar badge, but the
  failing node gets no red border/badge. Data already exists; read
  `getNodeMetrics(id).lastError` in BaseNode.
- **[P1] Shallow import validation** — only checks `flows` is an array
  (`flows.ts:1034-1036`); no node-type-registered check, no edge-endpoint
  validation, no deep-clone. Single-flow `importFlow` has none [tracked].
- **[P1] No spawn-at-cursor / tab-to-create** — the fuzzy search exists but the
  explorer is a modal and added nodes land at canvas center, not the pointer.
- **[P1] No fullscreen/perform mode** — the Control Panel surface is complete
  but there's no `requestFullscreen()`/chrome-hiding present mode.
- **[P2] No comment/annotation/backdrop**, no per-node user coloring (category
  only), no alignment/distribute, no live value-on-wire tooltips (port tooltips
  show name+type only).
- **[P3] No global transport** — there's a per-frame execution clock
  (`deltaTime`/`totalTime`/`frameCount`) but no BPM/`Tone.Transport`/timeline/
  cueing; tempo is per-node and wired manually.
- **[P3] `bindable` flag is defined but dead** (`nodes.ts:68`, validated, never
  consumed) — implement param-to-param binding/expressions or remove it.
