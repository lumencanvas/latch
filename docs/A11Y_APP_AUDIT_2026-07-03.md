# App-Wide Accessibility Audit — 2026-07-03 (Phase 4)

Companion to the later-50/51 **control-surface** a11y work. That pass covered the
declarative-UI control surface only (ControlRenderer, NodeView, the 4 canvas
editors, PropertiesPanel). This pass audits **everything else**: the node canvas
& wiring, the layout chrome, modals, the node explorer, and the connections/assets
surface.

## Method

A 5-agent read-only audit (one per surface) → adversarial verify of every finding
(reject not-real / already-done / out-of-scope / nit). **35 raw findings → 33
confirmed, 2 rejected.** Each confirmed finding is WCAG-grounded and cites the real
offending markup/CSS. Severity distribution: **16 high · 15 medium · 2 low.**

Out of scope (already fixed, not re-audited): `components/controls/*`,
`layout/PropertiesPanel.vue`, `_archived/`.

---

## Increment 1 — Modal/dialog focus management **[DONE]**

One shared composable, `composables/useDialogA11y.ts` (focus move-in on open ·
Tab focus-trap · focus restore to opener on close · Escape-to-close), applied to
all 8 dialogs. Each dialog also gained `role="dialog"` + `aria-modal="true"` +
`aria-labelledby` (heading `id`), an accessible-named close button, and — for the
two with live status — a `role="status"` toast. The AIModelManager toggle
checkboxes were switched from `display:none` (unfocusable) to the
visually-hidden-but-focusable pattern + a `:focus-visible` ring on the faux switch.

Dialogs migrated: `NodeExplorerModal`, `AIModelManagerModal`, `CodeEditorModal`
(keeps its Ctrl+S), `ShaderEditorModal`, `ConnectionManagerModal`, and the
`FlowTabs` rename + delete modals.

Composable is TDD + mutation-verified (7 tests; 5 mutations each confirmed red).
Browser-smoke confirmed (system Chrome): dialog role + `aria-labelledby` resolve,
focus moves into the dialog on open, Escape closes, and the toggle checkbox is
`display:block`/`opacity:0`/focusable — 12/12 checks, 0 real console errors.

**Findings closed:** #F7 (FlowTabs modals), #M11 (role/aria), #M12 (focus move-in),
#M13 (focus trap), #M14 (focus restore), #M15 (toggle display:none), #M26 (Escape
close), #M27 (Escape on non-focusable overlay — fixed by moving focus in), #M28
(save toast live region), #M29 (unnamed close buttons). **10 of 33.**

> Note: the "modals" surface findings #M11–M14 each named one example file, but they
> describe the *same* defect shared across every dialog; the composable fixes the
> class, not just the cited instance.

## Increment 2 — Theme B: mouse-only `<div>`s → real controls **[DONE]**

The recurring LATCH bug-class. Where a row/card carries a nested action control, the
select area is wrapped in a real `<button>` with the action(s) kept as siblings (no
nested interactive); otherwise the element becomes a plain `<button>`. All gain
accessible names + focus-visible rings, and hover-only affordances now also reveal on
keyboard focus. Custom dropdowns gained listbox semantics + Escape; the flow tabs
became a roving-tabindex `tablist` with arrow/F2/Delete/Shift+F10 keys and a
focus-managed context menu (via `useDialogA11y`).

Closed (5 commits): #B2 (connection rows), #B4 (asset card) + #B23 (asset delete),
#B5 (debug rows), #B6 (flow tabs) + #B8 (context menu) + #B25 (tab close name),
#B9 (category filter) + #B10 (node palette), #B24 (template edit) + partial #B14
(template listbox semantics). Unit + mutation-verified where the component is
unit-mountable (asset/connection/debug/template); browser-verified for the
app-chrome that isn't (AppSidebar, FlowTabs). **≈14 more findings closed → ~24 of 33.**

## Increment 4 — Theme D: non-color cues (1.4.1) **[PARTIAL — 2 of 4 done, 2 deferred]**

The two mechanical cues were closed; the port/edge type-colour cue is a
visual-language decision (a shape/letter on every port across 208 nodes) and was
**deferred by the maintainer** — ports/edges stay visually identical for now.

- **Connection status badge (`ConnectionStatusBadge.vue`) — closed, and a real
  bug fixed along the way.** The badge was styled entirely with Tailwind utility
  classes, but this project ships **no Tailwind** (no config, not in
  `package.json`, nothing defines those classes). Proven live: a span with the
  badge's exact classes renders `0×0`, transparent, `border-radius: 0`. So the
  badge had been **invisible since it was introduced** (commit `1d4e5de`) — the
  "colour-only" finding was read from source, but in the app there was no dot at
  all. Rewritten onto real scoped CSS + design tokens so it renders (connected
  `--color-success` · connecting/reconnecting `--color-warning` + pulse ·
  disconnected `--color-neutral-400` · error `--color-error`), with **error drawn
  as a soft square** (the only non-circular state → the critical green/red pair is
  hue-independent). `role="img"` + `aria-label` name it. Unit + mutation-verified
  (5 tests / 4 mutations red); **browser-verified** against the compiled scoped
  CSS + rendered measurement (error = `rgb(239,68,68)` @ `2px` radius vs connected
  = `rgb(34,197,94)` @ circle; tokens resolve, 0 console errors).
- **Tag filter chips (`NodeExplorer.vue`) — closed.** Active state was the
  primary-colour fill alone; added a `✓` prefix on the active chip (the non-colour
  cue) + `aria-pressed`. Browser-verified: toggle flips `aria-pressed` false→true,
  text `ai`→`✓ ai`, primary fill preserved; the global `:focus-visible` ring
  covers the chip (no `.tag-chip` outline suppression). App-chrome → browser-only.

**Deferred (maintainer decision — visual-language call, not a regression):**
| WCAG | Finding | File | Status |
|---|---|---|---|
| 1.4.1 A | Port data type conveyed by colour alone on the handle | BaseNode.vue | deferred |
| 1.4.1 A | Edges convey data type by colour only | AnimatedEdge.vue | deferred |

> Coupled decision: a port and its edge must share one type cue, so they're one
> design choice (shape-per-type / letter badge / edge dash pattern). Revisit with
> a concrete mockup pass.

**Closes the 2 mechanical D findings → ~32 of 33** (the 2 port/edge D findings deferred).

## Remaining backlog (Theme F + low)

### Theme F — canvas keyboard operation (the headline; multi-increment) — **Increments 1–3 DONE (select · move · wire)**

| WCAG | Finding | File | Status |
|---|---|---|---|
| 2.1.1 A | Node canvas has no keyboard idiom — cannot select, move, or wire nodes without a mouse | EditorView.vue | **CLOSED — select + move + wire all keyboard-operable** (inc 4 polish optional) |

Grounded in a 7-agent design workflow (recon → 3 independent proposals → adversarial synthesis; all
file/line refs verified against real code). Recommended model + increment plan in `docs/HANDOFF.md` later-55.
Sequenced 1→4: **1 select/nav (done)** · 2 move · 3 wire · 4 polish/composable.

**Increment 1 (done, browser-verified):** `.editor-view` is now a `role="application" tabindex="0"` host
mirroring the 4 control editors' idiom — a store-backed keyboard **cursor** (`ui.canvasCursor`) roves nodes
with Arrow keys (spatially sorted, wrapping, pan-into-view), **Enter/Space selects** (Shift = additive),
**Escape clears**; a `:focus-visible` ring on the host, a dashed `.kbd-cursor` node ring, an
`aria-live="polite"` region + `aria-valuetext` announcing every move/select, and `node.ariaLabel` on newly
added nodes. Delete works now that selection is keyboard-reachable (existing window handler); Cmd/Ctrl chords
pass through untouched. Browser smoke: focus + roving + select + clear + pass-through all confirmed, 0 console
errors.

**Increment 2 (done, browser-verified):** with a selection, Arrow keys **move** the selected node(s) by grid
step (Shift = 5× coarse); a burst of nudges collapses into one `Move node` undo entry (opened on first nudge,
closed after a 600 ms idle / any non-move key / blur), reusing the pointer drag-stop path
(`updateNodePosition` + `markDirty`); moves persist. Arrows navigate the cursor when nothing is selected and
move the selection when there is one (Escape deselects to return to browsing); pan only when a node nears the
viewport edge (unlike navigation, move must not re-centre each keystroke). Flow-coordinate smoke: directional
move (grid=20; coarse=100) · multi-select moves all 16 nodes together · **one undo reverts the whole burst** ·
redo restores · navigate-mode after Escape · **move persists across a full reload** · 0 console errors. Caught
+ fixed a real bug in the process: a bare `Shift` keydown (the leading half of Shift+Arrow) was splitting the
move history batch — bare modifier keydowns are now ignored.

**Increment 3 (done, browser-verified):** keyboard **wiring**, built from scratch. `w` on the cursor node
starts a wire; a 3-stage machine — pick source output (↑↓, auto-picked if one) → pick target node (←→, only
nodes with a valid input, filtered by `validateConnection`) → pick target input port (↑↓, valid only) → Enter
commits — reuses the pointer `onConnect` path (`addEdges` + `flowsStore.addEdge`) in one `Add connection` undo
entry. Escape cancels, Backspace steps back (no dead-ends). New `ui.wireDraft` drives a **glow on the exact
source + candidate-target handles** in BaseNode (+ reveals those nodes' port labels); every stage is announced.
Store-truth smoke (viewport-independent, since `:only-render-visible-elements` makes DOM edge/coord counts
unreliable): `w`→source glow · port/target/target-port cycling · commit creates a **real new edge (store 18→19)**
that **persists across reload** · Escape cancels + announces · glow clears after commit · 0 console errors.
**Finding CLOSED** (select + move + wire). Increment 4 (optional): spatial nav, edge-cursor delete, rubber-band
ghost edge, extract a shared `useApplicationKeyboard` composable.

> Note: the tap-to-add palette path (`addNodeAtCenter` via `nodeAddNonce`) already covered node **adding**;
> increment 1 adds keyboard **select/navigate**; **move + wire remain**.
