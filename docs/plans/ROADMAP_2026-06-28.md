# LATCH Roadmap — Canonical Execution Order (2026-06-28)

**This document is the single source of truth for *what* gets built and *in what
order*.** The design docs own the *how*; this owns sequencing, phase names, and the
single home for every deliverable. It supersedes the per-doc phase labels
(POLISH `P0–P4`, EXTENSIBILITY `Phase A–E`) — those remain valid as design
references but defer here for sequencing.

Created to resolve the coherence audit's findings: one phase vocabulary; every
orphaned commitment (file format, accessibility, live/VJ, installation) gets a real
home; each shared fix has exactly one owning phase.

> **Relationship to older plans:** this roadmap is canonical for the 2026-06-28
> audit + strategy work. Pre-existing `docs/plans/` files (`MASTER_PLAN.md`,
> `MODERNIZATION_PLAN_2026.md`, `UI_REDESIGN_PLAN.md`, `NODE_CONSOLIDATION_PLAN.md`,
> etc.) predate it and may be stale (per the `node-library-backlog` memory) — verify
> before relying on them; where they conflict with this roadmap, this wins.

**Design references:** `EXTENSIBILITY_ARCHITECTURE_2026-06-28.md` (node/protocol/
model/UI architecture + abstractions), `POLISH_AND_ARCHITECTURE_PLAN_2026-06-28.md`
(canvas + snippets + audit-fix detail), `SUBFLOW_REBUILD_SPEC_2026-06-28.md`,
`FILE_FORMAT_SPEC_2026-06-28.md`, `SECURITY_MODEL_2026-06-28.md`,
`POLICIES_2026-06-28.md`, `../AUDIT_2026-06-28.md`, `../strategy/`.

**Conventions every phase obeys:** branch off `main`; no AI attribution in git;
each step ends with `typecheck` + `lint` + `test:unit` green and is individually
revertible; never claim a win on a DON'T-OVERCLAIM item (`strategy/05`).

## Phase vocabulary (the only one)

`Phase 0 … Phase 9`, executed roughly in order (0–2 are foundational and gate the
rest; 4 and 5 can overlap; 8–9 are later bets). Each deliverable below names its
**owning phase** so nothing is double-sequenced.

## Phase 0 — Foundations (must land before any schema-changing work)

Goal: the safety rails + the cheap high-value wins, with zero behavior regression.

- **File-format spec + implementation** (`FILE_FORMAT_SPEC`): documented JSON schema,
  stable opaque node IDs, deterministic key ordering, **layout (position/color/size)
  separated from logic**, export/import envelope **with import validation**, and the
  per-document + per-node `version` fields. *The strategic centerpiece; gates all
  schema-changing work; unblocks git-diff and future multiplayer.*
- **Node-data versioning + `migrate()`** plumbing; load-time migration; graceful
  **missing-node placeholder** (preserve data + wires, never shatter); sample-flow +
  old-version-fixture upgrade tests. (EXTENSIBILITY §10.)
- **Extensibility primitives, scaffolded alongside existing code** (no behavior
  change): `defineNode`/`NodeSpec` (EXTENSIBILITY §3 — the authoritative interface),
  `defineNodeState` + central lifecycle registry (§4), `engine/trigger.ts`
  (`TRIGGER`/`isHigh`/`risingEdge`, §5.1), typed `ctx.num/bool/str/trig` (§5.2), and
  `registry/nodeRegistry.ts` glob (§6) **with the count-equality + dup-id +
  default-export guard tests from the first commit**.
- **Independent quick-win correctness fixes** (owned here; do NOT re-sequence them
  into later phases): number control `:min`/`:max` + units/precision (127 controls);
  boundary type-coercion in `getNodeInputs`; texture traps (shader iChannel +
  displacement via `resolveEffectSource`; render-3d depth canvas-backed); edge-trigger
  `latch`/`sample-hold`; `random` sample-on-trigger; `power` finite-guard;
  oscilloscope/equalizer Tone-analyser `.dispose()`; clasp video-receive
  `captureStream` stop; single-input edge replacement honoring `multiple`; **undo for
  control/param edits**; **per-node error badge** (engine `lastError` → BaseNode).
- **Policies** (`POLICIES`): CI gate list, the `defineNode` deprecation policy, and
  the sustainability/governance framing (the last is maintainer-owned — flagged
  open).

> **Shared-fix single-home rule (resolves the audit's double-sequencing):** the
> min/max binding is fixed *once* here; when `NodeView`/`<ControlRenderer>` replaces
> the inline renderer in Phase 3, it *carries the same binding forward* (not a
> redo). The AI `error` *output* is owned by Phase 2 (`runModelInference`); the
> per-node error *badge* (engine→UI) is owned here, Phase 0.

## Phase 1 — De-monolith + kill the leak class

- Split `executors/index.ts` by category; barrels preserve the test import contract
  (the "must-not-break export list" in `POLICIES`).
- Convert all ~23 state groups to `defineNodeState`; delete the 23 imports + 23 gc +
  23 disposeAll hand-wiring; generic lifecycle loops authoritative. **Gate:** per-type
  create+delete leak test.
- Derive `PURE_NODE_TYPES` from `pure:true`. **Gate:** exact equality to the literal
  **24-id** set.

## Phase 2 — Register-once subsystems (security-hardened)

- **`defineProtocol`** + `protocolRegistry` + `ctx.connection()`; convert mqtt/ws/http
  executors; fix the BLE/Serial/MIDI drift (one folder each). (EXTENSIBILITY §7.)
- **Capability-scoped, user-approved connection access + trust tier**
  (`SECURITY_MODEL`) — the n8n-breach mitigation; the broker holds secrets, nodes get
  a scoped handle, never the credential.
- **`defineModel`** + `modelRegistry` + uniform `ModelAdapter` + `runModelInference`;
  **version-resolve (not last-writer-wins) + lazy-load**; auto `loading`/`progress`/
  `done`/`error` outputs; registry-populated model selects. (EXTENSIBILITY §8; fixes
  AUDIT §E across all AI nodes.)

## Phase 3 — Control system + declarative UI

- Unify the 2–3 control renderers into one `<ControlRenderer>`; unify `visibleWhen`/
  `showWhen` into one `when` (multi-key + operators).
- **`ui` schema + one `NodeView` interpreter** + closed widget registry +
  `validateUISchema`; **first-class `component?` escape hatch with the declarative↔
  code boundary documented up front** (EXTENSIBILITY §9 + amendment §0.5 #1).
- New control types (`xy`/`range`/`curve`/`gradient`); custom controls become
  first-class; drag-to-scrub; keyboard + ARIA on controls.

## Phase 4 — Canvas, onboarding & accessibility

- **Canvas toolbar + marquee selection + pan/zoom gestures** (POLISH Stream 2).
- **Snippets tab + `flowToPreview` thumbnails** (POLISH Stream 3); **templates on the
  empty canvas**; **drag-a-wire-into-empty-space → compatible-node suggestions**.
- **Accessibility (real home for the §0.5 #9 mandate):** keyboard-operable wiring
  (WCAG 2.5.7/2.1.1), non-color port-type cues (1.4.1), ARIA names for nodes/edges,
  modal focus traps.
- **On-wire debugging:** freeze-the-frame + per-port value preview/history;
  error-to-exact-node deep-linking.

## Phase 5 — Node functionality & the modulation gap *(can overlap Phase 4)*

- Add input ports to modulatable params (all `image-fx-*`; audio `wet`/`feedback`/`Q`/
  `ratio`/sidechain; 3D material/light color/emissive). (AUDIT §C.)
- New primitives: `atan2`, two-input `min`/`max`, `phasor`/`ramp`, an `edge` node, LFO
  `phase`+`reset`; a **feedback (frame-delay) visual node**; wire `blur.passes`; unify
  gain/volume units; filter response-curve control.
- Inline connection picker on the node body; **regenerate `connectivity.md`** from
  live defs (owned here).

## Phase 6 — Full per-node co-location *(the large tail — largest single item)*

- Codemod-assisted move of **all ~238 nodes** to `registry/<cat>/<node>/`; rename
  `_`-folders; resolve `counter`/`sample-hold` to one folder each; delete
  `components.ts` + `executors/index.ts`; migrate the ~29 bespoke SFCs to `ui` where
  feasible (canvas-heavy ones like oscilloscope stay `component`); widen `vitest`
  include. **Acknowledged: plausibly larger than the subflow rebuild; ship per
  category with the glob count-guard green each time.**
- **`latch new-node` scaffolding CLI**, isolated node test harness, inline "which
  folder failed and why."

## Phase 7 — Subflow rebuild *(gated on Phase 1 lifecycle — `defineNodeState`)*

- `expandGraph` flattening with instance-qualified ids; real `subflow` instance
  definition with dynamic typed ports; breadcrumb navigation; palette reuse/
  instancing; recursion guard; golden tests (independent state, async inside, GC on

## Phase 8 — Live/VJ + installation *(persona-critical; new homes)*

## Phase 9 — Big bet

- **Multiplayer co-editing + comments** (Figma LWW-per-property + fractional indexing
  on `@clasp-to`) — architected-for by Phase 0's stable-ID format.

## Always-on (every phase)

CI gates enforced (`POLICIES`): glob count-equality, must-not-break export list,
per-type leak test, exact pure-set, format round-trip, a11y lint. `defineNode` is a
frozen contract (deprecation-only). Big-graph perf discipline: selection/hover in
CSS not Pinia; decouple cosmetic edits from execution; profile 500+. Honest
messaging per `strategy/05` DON'T-OVERCLAIM.

## Explicitly deferred / out of current scope

Global boolean-port-type resolution; performance HUD; the dead `bindable` flag;
deep DMX/Art-Net beyond Phase-2 protocol work (needs Electron/`@clasp-to`).

## Dependency summary

`Phase 0` → everything (format + primitives + versioning are prerequisites).
`Phase 1` → `Phase 2/3/6/7` (the modular engine + lifecycle). `Phase 2` security →
any distributed/custom node handling connections. `Phase 3` `NodeView` → the SFC→`ui`
migration in `Phase 6`. `Phase 0` stable-ID format → `Phase 9` multiplayer.
