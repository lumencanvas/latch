# LATCH Project Policies — CI, API Deprecation, Governance (2026-06-28)

The cross-cutting policies the plan corpus depends on but never defined: how CI
**enforces** the guard tests, how the `defineNode` "frozen contract" actually works,
and who owns sustainability. Referenced by `ROADMAP` (always-on) and EXTENSIBILITY
§0.5 #5/#7. Fulfills `strategy/06` §7 missing-items.

---

## 1. CI gates (enforced on every PR)

The plans scatter "guard tests" and say "CI must enforce them" without defining CI.
This is the enforced list. A PR is red if any fails.

| Gate | What it asserts | Phase it activates |
|------|-----------------|--------------------|
| **typecheck / lint / unit** | `vue-tsc --noEmit`, eslint, `vitest run` green | always |
| **Registry count-equality** | `Object.keys(nodeSpecs).length === legacy allNodes.length` (catches an empty/partial glob) | Phase 0 |
| **Default-export lint** | every `registry/**/node.ts` has a default `defineNode(...)` export | Phase 0 |
| **Dup-id throw** | no node id defined in two places (incl. `counter`/`sample-hold`) | Phase 0 |
| **Must-not-break export list** | every named export in the documented list still resolves from `@/engine/executors{,/<cat>}` and `@/registry` (`CUSTOM_NODE_TYPE_IDS`) | Phase 1+ |
| **Pure-set exact equality** | derived `PURE_NODE_TYPES` === the literal 24-id set (membership, not size) | Phase 1 |
| **Per-type leak test** | create+delete one node of each stateful type in dirty mode → its state Map empties | Phase 1 |
| **Format round-trip** | load→save unchanged flow = byte-identical; move-node touches only `layout` | Phase 0 |
| **Legacy/missing-node load** | v1.0 sample-flow migrates; unknown type → placeholder with data+wires | Phase 0 |
| **Prompt-format contract** | every text-gen model spec has `load.promptFormat` | Phase 2 |
| **a11y lint** | controls/handles have ARIA roles/labels; no color-only port encoding (axe rule subset) | Phase 4 |
| **Big-graph perf budget (advisory)** | render fan-out / cosmetic-edit-no-execute check at 500 nodes | Phase 1+ |

The **must-not-break export list** is maintained as a checked-in fixture
(`tests/contracts/public-exports.ts`); adding/removing a public export is a
deliberate, reviewed change.

## 2. `defineNode` API deprecation policy

`defineNode`/`NodeSpec`/`defineProtocol`/`defineModel`/the `ui` schema are a **public
contract** for node authors. Rete v1→v2 and ComfyUI V3 stranded their communities by
rewriting; LATCH commits to the opposite.

- **API version** = the LATCH minor version that introduced/changed a contract field.
- **Additive within a major:** new optional fields only; never repurpose or remove an
  existing field within a major version.
- **Deprecation, never silent removal:** to retire a field, mark it
  `@deprecated` in the TS types + emit a dev-console warning naming the replacement;
  keep it working for **at least one full major version** (≥ ~2 release cycles).
- **Migration provided:** any contract change that affects saved flows ships a
  node-data `migrate()` (FILE_FORMAT_SPEC) so old flows upgrade automatically.
- **Stable node-type IDs forever:** a node's `type` id (and a custom node's id) is
  permanent — renaming requires an alias/redirect, never a breaking change (Blender's
  "type number must never change" lesson).
- **A breaking `defineNode` v2 is a last resort:** if ever unavoidable, ship a
  compatibility shim that loads v1 specs, with a documented codemod — no flag day.

## 3. Sustainability / governance (maintainer-owned — OPEN)

`strategy/06` flags this **"Critical"**: a free/open tool whose pitch is "your work
outlives any company" must itself have a survival story, or LATCH ironically becomes
the next discontinued tool it markets against. This is a **non-code decision only the
maintainer can make**; this doc frames it, it does not decide it.

Open questions to resolve:
- **License:** confirm a genuinely OSI-open license (not "fair-code") and state it
  plainly — honest labeling is itself a trust advantage (the n8n lesson). *(Verify
  the repo's current `LICENSE`.)*
- **Funding/maintenance model:** what keeps LATCH alive? (options, not
  recommendations: individual stewardship + sponsors; a foundation/Open Collective;
  grant funding like Cables' NLnet/NGI; a commercial host/services tier funding the
  open core). Each has tradeoffs; pick deliberately.
- **Governance:** solo-maintainer vs. contributors vs. eventual stewardship; how
  decisions + releases are made; bus-factor.
- **Durability guarantees to publish:** the open format spec (done — FILE_FORMAT_SPEC),
  guaranteed export, self-host instructions, and a written "we will never orphan your
  files" commitment. These turn the positioning (`strategy/05`) from a slogan into a
  policy.

**Recommendation:** treat the durability guarantees as shippable now (they're mostly
documentation + the format work already planned); treat license-confirmation as a
quick must-do; treat funding/governance as a maintainer decision to make before
marketing the durability narrative publicly — so the promise isn't hollow.
